*** NOTE on architecture vs. the altacv setup
altacv's =\cvevent= prints a header line inline into a flowing =paracol=
column, so a following org paragraph or native =- item= list simply
continues in the same column. That is why [[file:../org-resume/curriculum_AndreasLoehr.org][=org-resume/curriculum_AndreasLoehr.org=]]
can be written in almost pure org.

moderncv is different. =\cvitem{hint}{body}= and =\cventry{...}= build one
self-contained two-column *row* per call: everything for the row has to sit
inside the argument. A native org list written *after* a =\cventry= is no
longer inside that argument, so it typesets at full page width, outside
moderncv's main column, and the layout visibly breaks. This is the same
constraint documented in [[file:../1.5-column-cv/cv-template.org][=1.5-column-cv/cv-template.org=]].

*** NOTE on the cvblock environment
=cvblock= is the way around that. Instead of a command that closes its own
row, it is an *environment* that opens the hint column and the main column
and leaves the main column open, so arbitrary org content — paragraphs,
=- item= lists, =*bold*=, =/italic/=, links — is emitted inside it and lands
in the right place. Usage:

: #+ATTR_LATEX: :options {11/2024 -- present}
: #+begin_cvblock
: *Job Title*, Employer, /City/
:
: Prose.
:
: - a bullet
: #+end_cvblock

Two things to get right:

1. The =#+ATTR_LATEX:= line must sit *immediately* above =#+begin_cvblock=
   with no blank line between them, or the argument is dropped and the
   build fails with a missing-argument error.
2. The braces in =:options {...}= are required — =cvblock= takes one
   mandatory argument, and =:options= is passed through to LaTeX verbatim.

Because =:options= is verbatim, do not put =&=, =%= or =#= in a hint; write
=\&=, =\%=, =\#=.

=cvblock= is a LaTeX =list=, deliberately, rather than the tabular/minipage
pair moderncv itself uses: a =list= breaks across a page boundary, a minipage
does not, so a long entry flows onto the next page instead of being pushed
there whole.

*** NOTE on what stock org export breaks under moderncv
moderncv does *not* =\LoadClass{article}=; it only inputs the size =.clo=
file. Several things org emits by default therefore have nothing to land on:

- =#+begin_quote= → =\begin{quote}=. moderncv defines =\quote{...}= as a
  one-argument *command* for the header blurb, so the =quote= *environment*
  does not exist and the block silently eats its first group instead of
  erroring cleanly. Use a =cvblock= or plain emphasis. The header blurb is
  the =\quote{...}= call in the CV Header block.
- =#+CAPTION:= on an image or a table → =\begin{figure}= / =\begin{table}=
  → undefined environment; moderncv has no float machinery. Uncaptioned
  tables are fine (=center= + =tabular= are both in the LaTeX kernel).
- =#+begin_verse= → undefined environment.
- An =ALT_TITLE= property or a footnote in a headline makes org emit
  =\section[alt]{title}=, which breaks moderncv's =\section= xparse
  signature. Do not use either in this file.
- Footnotes are listed in moderncv's =KNOWN_BUGS= as erroring; the output is
  reportedly still correct under =-interaction=nonstopmode=.
- =\hypersetup{...}=: org writes it into the *preamble*, but moderncv loads
  hyperref from =\AtEndPreamble=, which only fires at =\begin{document}= —
  so it would be an undefined control sequence. The LaTeX Config block sets
  =org-latex-hyperref-template= to nil to suppress it; moderncv fills in
  pdfauthor and pdftitle itself from =\name= and =\title=.
- Org writes =\title{}=, =\author{}= and =\date{}= into the preamble
  unconditionally — =#+OPTIONS: title:nil= suppresses only the title
  *command*. moderncv =\renewcommand*=s both =\title= and =\date=, so
  =#+TITLE:= at the top of this file *is* the tagline under the name, and
  the cover letter has to re-issue =\date{...}= in the body because an
  empty =\date{}= from org would otherwise blank moderncv's =\today=.

*** NOTE on publications
moderncv's own =KNOWN_BUGS= file lists it as incompatible with *biblatex*
and with *biber* — which is precisely the toolchain the altacv CV uses
(=\addbibresource= plus =\printbibliography=). That cannot be carried over
here.

The two entries in [[file:andy.bib][=andy.bib=]] are therefore written out by hand in the
Publications section below. That is not purely a workaround: =plain.bst=,
the style moderncv's own BibTeX route would use, prints neither the =url= of
the arXiv entry nor the =doi= of the WSC entry, so for two references the
automated output would be strictly worse than the hand-written one.

If the list grows enough to be worth automating, the BibTeX route is:

: \renewcommand*{\bibliographyitemlabel}{[\arabic{enumiv}]}   % in the preamble
: \nocite{*}                                                  % in the section
: \bibliographystyle{unsrturl}
: \bibliography{andy}

=unsrturl= rather than =plain=: it ships with TeX Live and does print URLs.
=andy.bib= stays in this directory as the source of record either way.

*** NOTE on colours (the ordering is load-bearing)
moderncv exposes exactly three colours: =color0= (body), =color1= (primary
accent) and =color2= (secondary accent). =\moderncvstyle= then aliases the
semantic names off them — =\colorlet{sectioncolor}{color1}=,
=\colorlet{bodyrulecolor}{color1}=, =\colorlet{titlecolor}{color2}= and so
on. =\colorlet= *snapshots* the value at that moment.

So the order in the preamble must be:

: \moderncvcolor{grey}     →  override color0/1/2  →  \moderncvstyle{classic}

Redefining =color1= *after* =\moderncvstyle= changes nothing about the
section headings — it looks like it worked, and the CV comes out in moderncv's
stock palette. Semantic names can still be overridden individually after the
style, which is what the second block of =\colorlet=s in the preamble does.

*** NOTE on compiler

with pdflatex, which is what =#+LATEX_COMPILER= below selects. The
=org-latex-pdf-process= override above is kept anyway so that switching to
xelatex or lualatex later is a one-line change; a hardcoded =latexmk -pdf=
would silently ignore =#+LATEX_COMPILER=. Command-line builds are covered by
[[file:.latexmkrc][=.latexmkrc=]] in this directory.
